# 메모 관리 애플리케이션 (Memo Management App)

본 프로젝트는 React를 기반으로 한 메모 관리 서비스입니다.

## 1. API 파일 구조 및 역할

데이터 통신 로직을 컴포넌트와 분리하여 유지보수성을 높였습니다.

- **`client.js`**: Axios 인스턴스를 설정하는 파일입니다. API의 `baseURL`을 설정하고 공통 설정을 관리하여 중복 코드를 방지합니다.
- **`memos.js`**: 비즈니스 로직에 필요한 통신 함수(`getMemos`, `createMemo`, `updateMemo`, `deleteMemo`)들이 정의되어 있습니다. UI 컴포넌트는 이 함수들을 호출하여 서버와 데이터를 주고받습니다.

## 2. 상태 UI 3종 세트 설명

사용자가 데이터의 상태를 직관적으로 파악할 수 있도록 세 가지 상태 UI를 필수 구현했습니다.

- **Loading**: `isLoading` 상태가 `true`일 때 노출됩니다. 데이터를 가져오는 중임을 알리는 스피너와 메시지를 보여줍니다.
- **Error**: 통신 실패 시 `error` 객체에 메시지를 담아 노출합니다. 사용자가 즉시 통신을 다시 시도할 수 있도록 **'다시 시도'** 버튼을 포함합니다.
- **Empty**: 로딩과 에러가 없으나 데이터 결과가 0개일 때 노출됩니다. "메모가 없습니다"라는 메시지와 함께 **'첫 메모 작성하기'** 버튼을 통해 사용자의 행동을 유도합니다.

## 3. CRUD 구현 및 상태 관리

React의 불변성 원칙과 효율적인 배열 메서드를 활용하여 상태를 관리합니다.

- **Create (생성)**: 새로운 메모가 성공적으로 생성되면 서버의 응답 데이터를 받아 기존 리스트의 맨 앞에 추가합니다(`[newMemo, ...prev]`).
- **Update (수정)**: **Map 패턴**을 사용하여 수정된 메모의 ID와 일치하는 항목만 교체하고, 나머지 리스트는 그대로 유지하여 불필요한 렌더링을 방지합니다.
- **Delete (삭제)**: **Filter 패턴**을 사용하여 삭제된 메모의 ID를 제외한 새로운 배열을 상태에 반영함으로써 즉각적으로 UI를 갱신합니다.

## 4. 선택 확장 과제 구현 사항

사용자 편의성을 높이기 위해 다음과 같은 기능을 추가 구현했습니다.

- **검색 즉시 반영 금지**: 실시간 입력값(`inputValue`)과 실제 검색 쿼리(`searchQuery`)를 분리하여 사용자가 검색 버튼을 누를 때만 API 요청이 발생하도록 최적화했습니다.
- **페이지네이션 (Pagination)**: 서버 API의 `page`, `pageSize`를 활용하여 데이터를 나누어 조회하며, 하단 컨트롤러를 통해 페이지를 이동할 수 있습니다.
- **핀 고정 (Pinning)**: 중요 메모를 최상단에 배치하는 기능입니다. 정렬 로직에서 핀 상태를 1순위 조건으로 설정하여 사용자가 고정한 메모를 놓치지 않게 했습니다.
- **정렬 (Sorting)**: 최신순과 오래된순 필터를 제공하며, 핀 고정 항목은 정렬 기준과 관계없이 항상 최상단에 위치합니다.
- **선택 삭제 (Batch Delete)**: 체크박스로 여러 메모를 선택한 후, 한 번의 클릭으로 일괄 삭제할 수 있는 기능을 구현했습니다.

## 5. 기술 스택 및 디자인

- **Font**: Gmarket Sans (Bold/Medium)를 적용하여 타이틀과 본문의 시각적 대비를 강조했습니다.
- **Library**: React, Axios
- **Styling**: Vanilla CSS (Flexbox를 활용한 수직 중앙 정렬 및 반응형 레이아웃 구현)
