10강: useReducer (복잡한 상태 관리)

Topic: Reducer BasicsQ1 - Q5

Q1. useState가 불편해지는 증상이 아닌 것은?

정답: state 값이 숫자 1개뿐이라 단순함

Q2. useReducer의 핵심 개념으로 올바른 것은?

정답: 상태 변경 규칙을 reducer로 분리하고, action으로 상태 전이를 요청하는 방식

Q3. useReducer의 기본 문법으로 올바른 것은?

정답: const [state, dispatch] = useReducer(reducer, initialState)

Q4. useReducer의 흐름으로 올바른 순서는?

정답: dispatch(action) → reducer 실행 → 화면 갱신

Q5. action 설계 원칙으로 올바른 것은?

정답: action은 "무엇이 일어났는지"를 표현하고, payload는 최소한의 데이터만 담는다
Topic: Reducer RulesQ6 - Q10

Q6. reducer의 3대 원칙에 해당하지 않는 것은?

정답: reducer 안에서 API 요청을 보내야 한다

Reducer는 순수 함수여야 하므로 사이드 이펙트(API)는 허용되지 않습니다.

Q7. 다음 중 reducer에서 잘못된 코드는?

정답: state.items.push(newItem); return state;

불변성을 지키지 않고 원본 배열을 직접 수정했습니다.

Q8. useReducer로 전환을 고려해야 하는 상황으로 적절하지 않은 것은?

정답: 카운터 하나만 관리할 때

Q9. dispatch 했는데 화면이 안 바뀌는 가장 흔한 원인은?

정답: reducer에서 불변성을 위반해서 (같은 참조 반환)

Q10. useReducer와 useState 비교로 올바른 것은?

정답: useReducer는 규칙을 한 곳에 모아 예측 가능하게 만드는 것이 목적이다

11강: Context API (상태 공유)

Topic: Context BasicsQ11 - Q15

Q11. props drilling의 문제점이 아닌 것은?

정답: 부모에서 자식으로 1단계만 props를 전달함

Q12. Context에 대한 설명으로 올바른 것은?

정답: Context는 Provider로 감싼 트리 안에서만 공유되는 "필요한 범위의 공유"이다

Q13. Context 사용 3단계의 올바른 순서는?

정답: createContext → Provider → useContext

Q14. 다음 중 Context에 넣기 적합한 값은?

정답: 여러 컴포넌트에서 공유하는 다크모드 theme

Q15. Context 분리 전략으로 올바른 것은?

정답: 기능 단위로 ThemeContext, ModalContext 등으로 분리한다
Topic: Advanced ContextQ16 - Q20

Q16. useContext()가 null/undefined를 반환하는 가장 흔한 원인은?

정답: Provider로 컴포넌트를 감싸지 않았거나, 범위 밖에서 사용해서

Q17. Provider의 value 설계로 올바른 것은?

정답: 값과 변경 함수(toggleTheme 등)를 함께 객체로 넣는다

Q18. createContext(defaultValue)에서 defaultValue의 역할은?

정답: Provider 없이 useContext를 사용할 때의 기본값

Q19. Context 전용 Hook 패턴(useTheme 등)의 장점이 아닌 것은?

정답: Context 사용 시 자동으로 성능이 최적화된다

자동 성능 최적화는 없으며, 별도의 메모이제이션 처리가 필요합니다.

Q20. Context와 useReducer를 함께 사용하는 패턴의 설명으로 올바른 것은?

정답: useReducer로 상태 로직을 정리하고, Context로 여러 컴포넌트에서 공유할 수 있다
