Topic: Query & Cache (Q1 - Q10)

Q1. React Query의 본질적인 역할은?

정답: 서버 상태(Server State)의 관리

서버 데이터를 페칭하고 캐싱하며, 업데이트하는 로직을 표준화한다.

Q2. useQuery의 필수 옵션 두 가지는?

정답: queryKey, queryFn

데이터를 식별할 키와 데이터를 가져올 비동기 함수가 반드시 필요하다.

Q3. Query Key를 배열로 관리하는 주된 이유는?

정답: 계층적 캐시 식별과 의존성 관리

배열 내부 값이 변하면 쿼리가 자동으로 다시 호출되게 만든다.

Q4. staleTime이 0일 때의 동작 방식은?

정답: 데이터를 즉시 '상한 것'으로 간주하여 매번 다시 요청한다

기본값이 0이므로, 별도 설정이 없으면 항상 백그라운드에서 신선도를 체크한다.

Q5. gcTime(구 cacheTime)은 언제 시작되는가?

정답: 해당 데이터를 사용하는 컴포넌트가 언마운트된 시점부터

사용되지 않는 데이터를 메모리에서 언제 지울지 결정하는 타이머가 작동한다.

Q6. isLoading과 isFetching의 차이는?

정답: 초기 로딩(데이터 없음) vs 전체 페칭 상태

isLoading은 캐시가 아예 없을 때만 true, isFetching은 백그라운드 갱신 시에도 true가 된다.

Q7. useMutation을 사용하는 주된 상황은?

정답: 서버 데이터를 변경(CUD)하는 요청을 보낼 때

POST, PUT, DELETE 요청처럼 서버 상태를 변형하는 액션을 처리한다.

Q8. Mutation 성공 후 데이터를 최신화하는 표준 기법은?

정답: invalidateQueries 호출

관련된 키의 캐시를 무효화하여 컴포넌트가 최신 데이터를 다시 불러오게 한다.

Q9. enabled 옵션의 유용한 활용 사례는?

정답: 검색어가 비어있을 때 API 호출을 막는 경우

의존성 변수가 준비되지 않았을 때 쿼리가 실행되지 않도록 지연시킨다.

Q10. React Query를 앱 전체에서 쓰기 위해 감싸야 하는 컴포넌트는?

정답: QueryClientProvider

Context API를 기반으로 모든 하위 컴포넌트에 캐시 클라이언트를 전달한다.

Topic: Advanced & UX (Q11 - Q20)

Q11. API 에러 시 재시도 횟수를 조정하는 옵션은?

정답: retry

기본값은 3회이며, 특정 에러 코드에 따라 재시도 여부를 결정할 수도 있다.

Q12. 서버 응답 데이터에서 특정 필드만 골라내고 싶을 때 쓰는 옵션은?

정답: select

컴포넌트 내부에 복잡한 변형 로직을 두지 않고, 캐시 데이터에서 원하는 형태만 추출해 준다.

Q13. 사용자가 다음 페이지로 가기 전에 데이터를 미리 준비하는 기법은?

정답: prefetchQuery

마우스를 버튼에 올리는 등 특정 행동 시 미리 호출하여 체감 로딩을 0으로 만든다.

Q14. mutation 없이 캐시 데이터를 수동으로 수정하고 싶다면?

정답: setQueryData

서버 요청 없이 로컬 캐시를 강제로 업데이트할 때 유용하다.

Q15. getNextPageParam 옵션을 사용하는 쿼리 훅은?

정답: useInfiniteQuery

페이지네이션이나 무한 스크롤 구현 시 다음 페이지 번호를 계산하기 위해 쓴다.

Q16. 데이터가 아직 로딩 중일 때 보여줄 가짜 데이터를 설정하려면?

정답: placeholderData

초기 렌더링 시 레이아웃 깨짐을 방지하기 위해 정적인 기초 데이터를 제공한다.

Q17. 브라우저 탭을 이동했다가 돌아왔을 때 자동 갱신되는 원인은?

정답: refetchOnWindowFocus 설정 때문

최신 데이터를 보장하기 위한 기본 정책이며, 비활성화할 수도 있다.

Q18. Query Key 설계 시 주의해야 할 점은?

정답: 유일성을 보장하고 의존성 변수를 빠짐없이 포함해야 한다

의존성 배열을 빠뜨리면 값이 변해도 데이터가 새로고침되지 않는다.

Q19. 에러 발생 시 UI에 에러 메시지를 보여주려면 어떤 값을 체크하나?

정답: isError 상태와 error 객체

isError가 true일 때 에러 경계나 알림 메시지를 렌더링한다.

Q20. React Query가 지향하는 프로그래밍 스타일은?

정답: 선언적(Declarative) 데이터 페칭

데이터를 '어떻게' 가져오는지 일일이 지시하지 않고, 상태를 '정의'하는 방식이다.
